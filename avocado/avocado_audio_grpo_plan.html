🥑 Avocado：Audio-Domain Natural Caption GRPO 训练方案

从 HarperValley 强监督 who/what/when 转向通用音频 caption 的可验证信息增量：提高 MMAU、MMSU、MMAR 下游 QA 覆盖率，同时用 precision 与 hallucination gate 守住真实性。

Recommended route

先做快速强 prompt baseline，再做 base Qwen2.5-Omni-7B direct GRPO。若 GRPO 无效，优先修 reward，而不是用 SFT 掩盖问题。

Reward implication: 新 reward 不能继续只奖励“更严格”。它要奖励可验证的信息补全：提高 event/keypoint recall 与 QA utility，同时用 claim precision、unsupported-claim penalty 和 repetition gate 防止模型为了覆盖率而乱猜。

关键决策

是否改 prompt
改。新 prompt 为 prompts/general_audio_caption_v2.txt，要求自然语言 caption 覆盖 speech、music、sound event、order、background、voice、prosody；允许 calibrated language；继续禁止无声学证据的身份、职业、年龄、性别、地点、文化背景等确定性断言。
Baseline 策略
采用快速强基线。先跑 mmar_caption_general_v2 小规模 prompt ablation，选能提高 coverage 且不明显增加 wrong-answer/hallucination 的版本作为 GRPO baseline，然后直接训练。
训练顺序
主线先做 base Qwen2.5-Omni-7B + GRPO，证明 RL reward 设计有效；后续再做 SFT 与 SFT+GRPO。若 direct GRPO 无效，先修 reward/verifier，不用 SFT 掩盖。

方案总览

1. Failure Analysis 从现有 caption-QA artifacts 统计 missing、wrong、hallucination proxy、repetition、length finish。
2. Prompt v2 用覆盖优先但证据约束的自然语言 caption prompt，替换过度保守 baseline。
3. Caption Benchmark 构建 caption -> LLM parser -> event list -> Event F1/Precision/Recall 的通用评测。
4. GRPO Reward Event、Speech、QA-Utility、Length/Repetition、Safety gate 组合，并记录分项。
5. Evaluation 对比 prompt-v2 baseline 与 GRPO checkpoint 的 caption benchmark、MMAU、MMSU、MMAR。

Data & Benchmark

训练标注数据

  • 使用 qwen3.5-omni-plus 生成高覆盖 GT caption、event list、speech keypoints。
  • 借鉴 AVOCADO 的 QC：过滤太短、重复、信息缺失、过度推理样本。
  • 训练/验证/评测通过 sample ID、source ID、audio path 去重，避免 MMAU/MMSU/MMAR 泄漏。
  • 优先从 MMAU 等 benchmark 同源但不重叠的数据池和音视频数据集中抽音频。

Caption Benchmark v0/v1

  • 不复用 HarperValley grammar，也不强制 TACOS 时间戳评分。
  • v0 可改编 tacos-200-dedup 为无时间戳 event benchmark，但必须标注它只是快速投影。
  • v1 需要通用自然语言 caption：LLM parser 抽 event list，再做 semantic matching。
  • 报告 Event F1、Precision、Recall；Precision 近似 hallucination 反面，Recall 近似 miss 反面。

Reward Design

Reward 目的 实现要点 主要风险控制
Event 降低 Miss，同时不奖励无证据扩写。 GT event/keypoint recall + predicted claim precision；semantic matcher 或 verifier 判断支持关系。 Precision 低时压总分；unsupported claims 进入 hallucination penalty。
Speech 保留下游 QA 常用的说话信息。 speaker count、turn/order、quoted speech snippet、language、prosody、key spoken content。 不强制 HarperValley 时间戳；不奖励确定性年龄/性别/身份猜测。
QA Utility 让 caption 更能回答 benchmark 类问题。 离线从 GT 生成少量 answerable probes，在线奖励 caption 支持正确选择或明确答案事实。 probe 不暴露评测答案；只验证 caption 信息，不训练直接答题。
Length & Repetition 避免短漏、长循环和模板化空话。 按 GT event 数、speech 密度和音频长度给动态目标区间；重复 4-gram 与 length finish 计入惩罚。 长 caption 不自动高分，必须被 event/speech verifier 支持。
Safety Gate 守住真实性和可听证据边界。 身份、职业、精确年龄、性别、地点、文化背景等无证据确定性断言触发 penalty。 允许“sounds like / possibly / higher register”这类校准表达。

GRPO 实现路线

训练接口

  • 新增 general-caption dataset adapter，不依赖 HarperValley turns schema。
  • 保留 qwen2.5-omni-7b 作为基模，checkpoint 写到 /data3/fwh/temporal-audio-caption/。
  • 在线 reward 优先使用本地 verifier/entailment judge 批处理；qwen3.5-omni-plus 只用于离线标注和 QC。

训练日志

  • 记录 event recall、event precision、speech reward、QA utility。
  • 记录 length、finish reason、repetition ratio、unsupported-claim rate。
  • 每次 checkpoint 后跑固定 validation rollouts，保存 raw captions 与 reward breakdown。

Test & Acceptance

工程测试

  • 新增脚本跑 bash -n；新增 Python 模块跑 python -m unittest discover -s tests -v。
  • 训练、验证、评测 manifest 检查 missing、duplicate、unknown IDs。
  • 所有 raw captions、parsed events、reward breakdown、metrics、HTML report 都保存到 experiment directory。

验收标准

  • GRPO checkpoint 必须优于 prompt-v2 baseline 的 caption-event F1 或 MMAU/MMSU/MMAR composite。
  • Precision/hallucination 不能明显劣化；coverage 提升不能靠无证据扩写换来。
  • 如果 direct GRPO 无效，暂停 SFT+GRPO，先回到 reward verifier 和权重 ablation。

下一步应该做什么

立即下一步：用 prompts/general_audio_caption_v2.txt 对 MMAU/MMSU/MMAR 各抽 40-70 条做 stratified smoke ablation，复用现有 caption-QA pipeline 计算 coverage、answered accuracy、wrong-answer、length finish，并和当前 baseline 表逐项对比。

如果 coverage 明显提升且 wrong-answer 没有同步恶化，就冻结 prompt-v2 baseline，进入 caption-event benchmark v0 和 qwen3.5-plus 标注/QC pipeline。这个顺序最快暴露 reward 是否真的能补“信息不全”的核心问题。
